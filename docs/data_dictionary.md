# Data Dictionary

LearnPulse (fictional EdTech company). All data is synthetic, generated by
the scripts in `src/` with a fixed random seed (42).

- Enrollment window: 1 Sep 2025 – 31 Aug 2026
- Snapshot date: 30 Sep 2026 (no data after this date)

**How to read each table:** *Grain* says what one row means. The *primary key*
uniquely identifies a row. *Foreign keys* link to other tables.

---

## 1. students
**Grain:** one row = one student
**Primary key:** student_id
**Expected rows:** 20,000
**Answers:** Who are our learners and how did they find us?

| Column | Type | Nullable | Description | Example |
|---|---|---|---|---|
| student_id | INT | No | Unique student identifier | 10001 |
| signup_date | DATE | No | Date the account was created (on or before first enrollment) | 2025-12-24 |
| city | TEXT | No | Student's city | Bengaluru |
| city_tier | TEXT | No | Tier 1 / Tier 2 / Tier 3 | Tier 1 |
| age_group | TEXT | No | 18-22 / 23-27 / 28-35 / 35+ | 23-27 |
| background | TEXT | No | Student / Working (tech) / Working (non-tech) / Career break | Working (tech) |
| acquisition_channel | TEXT | No | Organic / Paid Social / Google Ads / Referral / YouTube / Partner College | Referral |
| device_type | TEXT | No | Mobile / Desktop | Mobile |

**Known quality issues:** ~5% inconsistent city spellings (e.g. "Bangalore" vs "Bengaluru").

## Relationships

```
students    1 ──< enrollments >── 1 courses
courses     1 ──< modules
enrollments 1 ─── 1 payments
enrollments 1 ──< exit_surveys      (0 or 1 per enrollment)
modules     1 ──< learning_activity
modules     1 ──< assessments
```

`1 ──<` means "one to many": one student can have many enrollments.

**Important join rule:** learning_activity and assessments have no enrollment_id.
To connect them to an enrollment, join on **both** student_id **and** course_id.
Joining on student_id alone would mix up a student's different courses.
